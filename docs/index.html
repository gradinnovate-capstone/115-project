01
W01 · 模型基礎 · 入門

Attention

從固定向量，到動態對齊

讀懂模型如何在生成每個詞時，選擇輸入序列中相關的資訊。先理解跨序列的 alignment，再進入 self-attention。

先備知識　向量內積、softmax、encoder–decoder

從原始資料開始

  • Neural Machine Translation by Jointly Learning to Align and Translate ↗Bahdanau, Cho & Bengio · 2014 / ICLR 2015
  • Attention Is All You Need ↗Vaswani et al. · 2017 · 延伸到 self-attention
展開導讀與實作 ＋

三個核心觀念

  1. Bahdanau attention 讓 decoder 對不同輸入位置給予不同權重，緩解把整段輸入壓成固定向量的瓶頸。
  2. Transformer 使用 query 與 key 計算相容性，再以權重加總 value；Q、K、V 是可學習投影產生的表示。
  3. Self-attention 的 Q、K、V 來自同一序列；cross-attention 的查詢與被查詢表示來自不同序列。
Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V

閱讀路徑

先讀 Bahdanau 論文的模型與 alignment 圖，再讀 Transformer §3.2。對每個矩陣標註序列長度與特徵維度，追蹤最後輸出為何仍是一串向量。

動手實作 課程設計

建立三個 token 的 Q、K、V，手算一列 attention weights；用 Python 重算並比較。再加入 causal mask，確認被遮住的位置機率為 0。

交付成果

一頁矩陣維度圖、手算結果、含 causal mask 的小程式。

讀完，試著回答

attention 權重總和為何是 1？

每個 query 對所有可見 key 的分數做 softmax，得到正值且總和為 1 的權重；是逐列正規化。

注意力最大的 token 就是答案的因果解釋嗎？

不能直接如此推論。權重只描述模型內部的一個運算步驟；若要主張因果關係，需要介入或消融實驗。

辨析　Bahdanau 的 additive attention 與 Transformer 的 scaled dot-product attention 不是同一公式。

W02–03 · 模型基礎 · 核心

Transformer → LLM

從架構，到 next-token prediction

串起 Transformer、因果語言模型與 in-context learning，理解「模型架構」「預訓練目標」「使用方式」是三個不同層次。

先備知識　Attention、交叉熵、梯度下降

從原始資料開始

  • Attention Is All You Need ↗Vaswani et al. · 2017 · NeurIPS
  • Language Models are Few-Shot Learners ↗Brown et al. · 2020 · NeurIPS（GPT-3）
展開導讀與實作 ＋

三個核心觀念

  1. 原始 Transformer 是 encoder–decoder 翻譯架構；GPT 類自回歸模型使用因果遮罩，逐步預測下一個 token。
  2. 一個 Transformer block 結合注意力、前饋網路、殘差連接與正規化；位置資訊讓模型能利用序列順序。
  3. GPT-3 論文探討以提示中的示例完成新任務；few-shot 推論本身不進行梯度更新。
L = −Σₜ log p(xₜ | x₁, …, xₜ₋₁)

閱讀路徑

Transformer 先讀架構圖與 §3，再看訓練設定；GPT-3 先看 zero / one / few-shot 的定義，再挑一種任務比較結果與限制。

動手實作 課程設計

畫出 encoder–decoder 與 decoder-only 資訊流；選 20 個固定分類樣本，比較 zero-shot 與 three-shot。保持模型、樣本與輸出格式相同。

交付成果

架構對照圖、固定測試集、正確率與失敗案例。範例不得取自測試集。

讀完，試著回答

few-shot 提示等於微調嗎？

不等於。提示改變輸入上下文；微調透過訓練更新參數。

訓練為何能平行處理，而生成通常逐步進行？

訓練時已知完整真實序列，遮罩阻止偷看未來；自回歸生成時下一個 token 依賴先前剛生成的內容。

辨析　next-token loss 下降不等於每種下游任務都改善；需另外評估事實性、任務成功率與成本。

W04 · 模型基礎 · 實作

nanoGPT

親手走完一次訓練迴圈

用小型字元語言模型串起資料、模型、loss、checkpoint 與 sampling。目標是理解訓練流程，不是重現大型模型算力規模。

先備知識　Python、PyTorch、Transformer

從原始資料開始

  • karpathy / nanoGPT ↗Andrej Karpathy · GitHub repo
展開導讀與實作 ＋

三個核心觀念

  1. 從 model.py 追蹤 token embedding、Transformer block 到 logits；從 train.py 追蹤 batch、loss 與參數更新。
  2. 先跑 Shakespeare 字元資料的最小實驗，再嘗試調整 context length 或模型深度。
  3. train loss 與 validation loss 必須分開記錄；生成樣本好看不能取代獨立評估。
資料 → token IDs → batch → logits → loss → backward → optimizer step

閱讀路徑

依 README 完成環境與資料準備，接著閱讀 model.py、train.py、sample.py。記錄使用的 commit SHA、套件版本與硬體。

動手實作 課程設計

依上游 README 的 CPU 小模型設定完成一次短訓練；固定 seed，只改 block_size 做兩次比較。把訓練時間、validation loss 與同提示生成樣本放在同一張表。

交付成果

可重跑的指令與設定、loss 圖、兩組生成樣本、200 字結果分析。

讀完，試著回答

為何 validation loss 上升時，train loss 仍可能下降？

模型可能開始記住訓練資料，對未見資料的泛化變差；也應檢查資料切分與評估噪音。

temperature 改變的是什麼？

取樣前的 logits 縮放與機率分布；它不會重新訓練模型或改變模型權重。

辨析　CPU 練習可用較小模型；不要把短訓練 loss 當成上游論文或大型 GPT 的重現成績。

W05 · 知識增強 · 核心

RAG

讓回答帶著可追溯的證據

把問題拆為「找得到資料嗎？」與「有根據地回答嗎？」。透過外部知識庫補充上下文，並分開衡量檢索與生成品質。

先備知識　Embeddings、相似度搜尋、LLM

從原始資料開始

  • Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks ↗Lewis et al. · 2020 · NeurIPS
展開導讀與實作 ＋

三個核心觀念

  1. 原始 RAG 結合可訓練的檢索器與 seq2seq 生成模型，把參數記憶與外部文件索引連接起來。
  2. RAG-Sequence 對整個輸出序列使用文件層級的邊際化；RAG-Token 允許不同 token 利用不同文件。
  3. 常見工程管線是切塊、索引、檢索與附證據生成；這是教學延伸，不等於重現原論文的聯合訓練。
問題 → 檢索 top-k 片段 → 組合上下文 → 回答 + 來源

閱讀路徑

先讀模型示意圖及 RAG-Sequence / RAG-Token 定義，再看 open-domain QA 評估。辨認 retriever、index 與 generator 各自的角色。

動手實作 課程設計

選 10–20 份可公開使用的文件，建立 20 題有標準證據的問答與 5 題無答案問題。比較不檢索與 RAG，逐題記錄 evidence hit@k、回答正確性及引用是否支持陳述。

交付成果

文件清單、切塊設定、問題與證據集、兩組結果、至少 3 個失敗案例。

讀完，試著回答

檢索到正確文件就保證回答正確嗎？

不保證。模型可能忽略、誤讀或錯引證據；檢索品質與生成忠實度要分別量測。

文件庫沒有答案時應怎麼做？

在評估規則中允許回答資料不足，並檢查模型是否編造內容或來源。

辨析　資料切塊、embedding 模型與 top-k 都會影響結果；比較時一次只改一個變因。

W06 · 知識增強 · 進階

GraphRAG

從局部片段，讀出整體主題

以 Microsoft GraphRAG 論文作為具體案例，理解實體關係圖與社群摘要如何支援跨文件、全局性的問題。

先備知識　RAG、圖的節點與邊、群集

從原始資料開始

  • From Local to Global: A Graph RAG Approach to Query-Focused Summarization ↗Edge et al. · 2024 預印本；2025 修訂
  • microsoft / graphrag ↗Microsoft · 官方實作
展開導讀與實作 ＋

三個核心觀念

  1. 論文從文件抽取實體與關係建立圖，再對相關實體社群預先產生摘要。
  2. 全局問題可先由社群摘要產生局部回答，再彙整成整體答案；這與只檢索少量近鄰片段不同。
  3. GraphRAG 是一類方法；此單元聚焦特定論文，不把所有使用 graph 的檢索系統視為相同實作。
文件 → 實體／關係 → 社群 → 社群摘要 → 全局回答

閱讀路徑

聚焦 indexing 與 global query 的流程，檢查論文如何定義 comprehensiveness 與 diversity，以及它們如何被評估。

動手實作 課程設計

沿用 RAG 文件集，建立 5 題局部事實題與 5 題全局主題題。比較 vector RAG 與 GraphRAG 的證據覆蓋、錯誤資訊、索引成本與回答延遲。

交付成果

一張可追溯至原文的實體關係圖、兩類問題比較表、使用情境建議。

讀完，試著回答

什麼問題適合先測 GraphRAG？

例如整份語料有哪些共同議題、組織間有哪些關係；仍須以實際資料與基準比較驗證。

圖中的邊一定是真的嗎？

不一定。抽取與合併可能出錯；保留來源片段，才能查核圖上的主張。

辨析　不可預設 GraphRAG 在所有題目都優於 vector RAG；索引成本與更新成本也應納入比較。

W07 · 知識增強 · 進階

LoRA

用低秩更新，適配模型行為

理解在凍結預訓練權重時，如何只訓練小型低秩矩陣。分清楚「補充外部知識」與「調整模型參數」的差異。

先備知識　矩陣乘法、微調、訓練與驗證切分

從原始資料開始

  • LoRA: Low-Rank Adaptation of Large Language Models ↗Hu et al. · 2021 / ICLR 2022
展開導讀與實作 ＋

三個核心觀念

  1. 凍結原權重 W₀，將更新寫為 BA；A 與 B 的中間維度 r 遠小於原矩陣維度。
  2. 對 d×k 的權重矩陣，低秩更新參數量為 r(d+k)，而非 dk；實際總量取決於套用哪些層。
  3. LoRA 是參數高效率微調方法；量化是另一項技術，不能直接把 LoRA 與 QLoRA 畫上等號。
W = W₀ + (α/r)BA； B ∈ ℝᵈˣʳ，A ∈ ℝʳˣᵏ

閱讀路徑

先讀方法與參數效率，再比較不同 rank、套用位置與基準設定。對任何節省比例，確認模型、硬體與比較對象。

動手實作 課程設計

先手算 d=k=4096、r=8 的可訓練參數；再選可負擔的小模型與固定格式任務，比較原模型、r=4、r=8。固定資料與訓練步數，記錄驗證分數及峰值記憶體。

交付成果

參數計算表、資料切分、訓練設定、品質與資源比較。無 GPU 可先提交線性層 LoRA 示範。

讀完，試著回答

4096×4096、rank 8 的更新有多少參數？

8×(4096+4096)=65,536；完整矩陣為 16,777,216。這只是單一矩陣，不是全模型節省比例。

rank 越高一定越好嗎？

不一定；資料規模、任務與過擬合都會影響結果，需固定其他條件評估。

辨析　LoRA 不保證模型記住的知識正確；時效性知識與來源追溯仍可能需要 RAG。

W08–09 · Agent 決策 · 實作

Learn Claude Code

理解 agent 周圍的執行環境

以 shareAI-lab 的教學 repo 學習 agent harness：模型如何提出工具呼叫、執行器如何回傳觀察，以及任務如何結束。

先備知識　Python、LLM API、JSON 與工具呼叫

從原始資料開始

  • shareAI-lab / learn-claude-code ↗社群教學 repo · 非 Anthropic 官方原始碼
  • Building effective agents ↗Anthropic · 2024 · 官方工程文章
展開導讀與實作 ＋

三個核心觀念

  1. Agent loop 在模型回應、工具執行與觀察之間循環；harness 管理工具介面、上下文與執行邊界。
  2. 先理解最小 loop，再閱讀任務管理、上下文壓縮與協作機制；課程目錄會演進，請記錄實際 commit。
  3. Workflow 以程式預先指定路徑；agent 可由模型動態選擇步驟。增加自主性也增加成本與失敗路徑。
任務 → 模型 → 工具請求 → 執行 → 觀察 → 模型 → 完成／停止

閱讀路徑

從 repo README 與最小 agent loop 開始，追蹤一個 tool call 的參數、回傳值與失敗處理。對照 Anthropic 文章的 workflow / agent 區分。

動手實作 課程設計

建立僅含文件讀取與搜尋的 agent，先使用模擬工具回應測試，再接模型。加入步數上限與錯誤回傳；設計成功、找不到文件、工具失敗三種任務。

交付成果

最小 loop、工具 schema、三份 action / observation 執行紀錄與停止條件。API 金鑰只放本機環境變數。

讀完，試著回答

工具失敗時應直接重試到成功嗎？

不應無限重試。限制次數、回傳可診斷的錯誤，並決定換策略或終止。

什麼情況先採固定 workflow？

任務步驟清楚、需要可預測輸出時；先建立簡單基準，再檢驗動態規劃的增益。

辨析　這個 repo 是理解概念的教學材料，不能據此推斷 Claude Code 產品完整的內部實作。

W10 · Agent 決策 · 進階

Decision Models

從軌跡學決策，到推理與行動

比較三個層次：Decision Transformer 從離線軌跡學策略；ReAct 將推理與行動交錯；工程架構決定如何執行與評估。

先備知識　Transformer、agent loop、reward / state / action

從原始資料開始

  • Decision Transformer: Reinforcement Learning via Sequence Modeling ↗Chen et al. · 2021 · NeurIPS
  • ReAct: Synergizing Reasoning and Acting in Language Models ↗Yao et al. · 2022 / ICLR 2023
  • Building effective agents ↗Anthropic · 2024 · Blog
展開導讀與實作 ＋

三個核心觀念

  1. Decision Transformer 以期望 return、歷史 state 與 action 為條件，使用因果 Transformer 預測行動；核心設定是 offline RL。
  2. ReAct 將推理與任務行動交錯，讓外部觀察參與後續選擇；它不是 Decision Transformer 的同義詞。
  3. 應比較任務成功率、工具次數、成本與錯誤恢復，不能只看模型輸出是否像在思考。
DT： (R̂₁, s₁, a₁, …, R̂ₜ, sₜ) → aₜ；R̂ₜ 為 return-to-go

閱讀路徑

先理解 DT 的軌跡表示與 return conditioning，再讀 ReAct 的互動案例。最後用工程文章選擇 routing、workflow 或 agent。

動手實作 課程設計

兩個小實驗：手工建立 3 條軌跡並計算 return-to-go；在固定 10 題文件查詢上，比較固定搜尋流程與動態工具選擇。保留每次操作與環境回應。

交付成果

軌跡資料表、兩種決策方式的架構圖、成功率／工具次數／延遲比較。

讀完，試著回答

把 desired return 設得很大，就會得到更好行動嗎？

不保證；若超出離線資料支持範圍，條件可能無法泛化。

ReAct 的文字推理能取代可驗證結果嗎？

不能。以工具回傳、最終輸出與任務判定為評估證據；文字理由本身不是正確性證明。

辨析　不要把 DT 的離線策略學習結果直接當作通用 LLM agent 決策能力的證據。

W11–12 · Agent 決策 · 研究

RSI

把自我改進變成可檢驗的假說

RSI 在此指 Recursive Self-Improvement（遞迴自我改進）。從理論與實驗兩條線閱讀，明確說出系統改了什麼、如何判定改善。

先備知識　Agent、實驗設計、訓練／驗證／測試切分

從原始資料開始

  • Goedel Machines: Self-Referential Universal Problem Solvers Making Provably Optimal Self-Improvements ↗Jürgen Schmidhuber · 2003 預印本
  • Darwin Godel Machine: Open-Ended Evolution of Self-Improving Agents ↗Zhang et al. · 2025 預印本
展開導讀與實作 ＋

三個核心觀念

  1. Gödel Machine 是以形式證明作為自我重寫條件的理論框架；保證依賴公理、效用與可證明性等設定。
  2. Darwin Gödel Machine 以修改 coding agent 程式與實驗評估探索改進，保存候選 archive，而非替每次修改提供形式證明。
  3. 需區分改提示、改工具／程式、改模型權重與改進改進器本身；觀察到分數提升不代表已證明無界 RSI。
候選版本 → 修改 → 固定評估 → 保留／淘汰 → 下一輪

閱讀路徑

先把兩篇論文的接受修改條件列成表，再檢查 DGM 的 benchmark、消融與實驗邊界。不要把理論最優性直接套到實驗系統。

動手實作 課程設計

建立最多 3 輪的改進實驗，每輪只修改一個工具描述或檢索設定。用開發集挑選候選，最後只在保留測試集評估一次；保留所有失敗版本。

交付成果

版本樹、固定評分器、開發／測試題目切分、每輪成本與得分、可否宣稱改善的結論。

讀完，試著回答

同一測試集反覆挑最佳版本，有什麼問題？

測試集逐漸變成開發集，容易選到對該集合過擬合的版本；最終需保留未參與選擇的測試集。

修改 agent 程式是否等於模型自己訓練自己？

不等於。程式層改進可在模型權重固定時進行，報告應清楚交代改動層次。

辨析　受限的小實驗只支持其資料與設定下的結論；不可延伸宣稱已達到通用、持續或無限制的自我改進。

找不到符合的單元，試試其他關鍵字或選擇「全部」。
